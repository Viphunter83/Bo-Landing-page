# Архитектура Мульти-тенантности (Multi-tenant Architecture)

Этот проект спроектирован как универсальный шаблон для ресторанного бизнеса. Основная идея заключается в полном разделении логики приложения, контента и визуального оформления.

## Ключевые компоненты

### 1. Tenant Config (`app/lib/config/tenant.ts`)
Центральное хранилище настроек для каждого бренда. Каждая конфигурация включает:
- **Branding**: Название, логотипы, слоганы.
- **Theme**: Набор HSL-токенов для CSS переменных (основной цвет, фон, текст, акценты).
- **Localization**: Поддерживаемые языки и валюты.
- **Features**: Флаги включения/выключения модулей (бронирование, доставка, лояльность).

### 2. Динамические Темы (`app/layout.tsx`)
В `RootLayout` внедряется блок `<style>`, который на лету генерирует CSS-переменные из конфигурации тенанта.
Пример внедряемых переменных:
```css
:root {
  --background: 240 10% 3.9%;
  --primary: 346.8 77.2% 49.8%;
  /* ... и так далее */
}
```
Это позволяет использовать классы Tailwind типа `bg-primary` или `text-foreground`, которые автоматически меняют цвет при смене тенанта.

### 3. Отвязка Контента (`app/data/content.ts`)
Все тексты на сайте используют переменные из `tenantConfig`. Например, вместо "Bo Restaurant" используется `tenantConfig.brand.name`.

## Переключение между клиентами

Для переключения используется переменная окружения:
`NEXT_PUBLIC_TENANT_ID`

Допустимые значения на данный момент:
- `bo` (Bo Restaurant, Dubai)
- `luna` (Luna & Co, Vietnam)

## Деплой

Каждый новый ресторан разворачивается как отдельный проект на Vercel, но использует один и тот же репозиторий GitHub. Разница заключается только в значении `NEXT_PUBLIC_TENANT_ID` в настройках проекта Vercel.
